# Tracking of 404 URLs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every 404 that spec 2 reports is merged in memory and written in batches as one row per URL
(per domain and culture) with a hit count, on SQLite and SQL Server, without touching the request pipeline.

**Architecture:** `NotFoundTracker` replaces `NoOpNotFoundRecorder` and writes normalised hits to a bounded
`Channel`. `TrackingFlushService` (hosted, per server) drains the channel into a lock-guarded pending buffer
every `FlushInterval` and upserts it through the shared EF Core `PageNotFoundTrackerDbContext`. The
`DbContext` is registered with Umbraco's `AddUmbracoDbContext<T>`; a provider (`ITrackingDatabaseProvider`,
one project per database, each with its own migrations) is chosen by Umbraco's provider name.
`TrackingMigrationService` migrates once Umbraco runs and opens the persistence gate.

**Tech Stack:** .NET 10, Umbraco 17.8.x, `Umbraco.Cms.Persistence.EFCore` (EF Core 10.0.x), `System.Threading.Channels`,
`TimeProvider`, NUnit + Moq, Umbraco integration test base, SQL Server 2022 in Docker / GitHub service container.

**Spec:** `docs/superpowers/specs/2026-11-01-tracking-design.md` (issue #3). Read it first; "Calls made in this
spec" is binding. Spec 2 (`2026-11-01-not-found-handling-design.md`) defines the call points.

## Global Constraints

- Branch `feature/3-tracking`, one PR to `develop`. Commits end with the session's `Co-Authored-By` line.
- Layering (`CLAUDE.md`): `.Core` = settings, models, contracts, entity; behaviour in `.Infrastructure`; providers in
  `Umbraco.Community.PageNotFoundTracker.Persistence.Sqlite` / `.Persistence.SqlServer`; entry project only wires.
- Settings under `Umbraco:Community:PageNotFoundTracker`: `TrackingEnabled` (default `true`), `FlushInterval`
  (default `00:01:00`), `IncludeQueryString` (default `false`), `ChannelCapacity` (default `10000`, writer's call).
  Read once at startup.
- No database write inside the request pipeline; the recorder never throws and never awaits I/O.
- Full channel: drop the new hit, warn at most once per minute with the number dropped since the last warning.
- Pending (merge + retry) buffer is bounded at `ChannelCapacity` identities; beyond it the entries with the oldest
  `LastSeen` are dropped (writer's call: one bound for both).
- Identity = normalised `Url` + `Domain` + `Culture`. `Domain`/`Culture` empty string, never null.
- Table `pageNotFoundTrackerUrl`; EF history table `__pageNotFoundTrackerMigrations` (SQL Server schema `dbo`).
- Timestamps are UTC `DateTime`, never `DateTimeOffset`.
- Unknown provider: one error log naming the provider, tracking off, site keeps serving.
- No discard operation (spec 5 adds it); the pending buffer, retry and in-flight batch are guarded by one lock.
- EF Core comes only through `Umbraco.Cms.Persistence.EFCore` `[17.8.0,18.0.0)`; mirrored in the entry csproj.
  `Microsoft.EntityFrameworkCore.Design` is `PrivateAssets=all`, pinned to the same EF Core version Umbraco resolves
  (10.0.12 at 17.8.0, check `packages.lock.json`).
- StyleCop zero warnings, copyright header, XML docs on public and internal members, `internal sealed` NUnit fixtures.
- SQL Server test-only values (never real): sa password `PnftTest-only1!`, local host port `14330`.
- Never commit `.sqlite.db` / `appsettings.json` changes from profile runs.

## Review Focus

1. A Umbraco domain name with a scheme or path (`https://www.sitea.local:44404/`, `localhost:44402/sitea`) and a
   request path that only starts with the prefix as text (`/siteab/x`): `RelativePath` strips the prefix only on a
   segment boundary (Task 2).
2. Malformed percent-encoding (`/%E0%A4%A`), `//double//slashes//`, `/` alone, and a 3,000-character path:
   normalisation never throws, root stays `/`, long values are truncated to the column limits, and the hash
   still uses the full value (Task 2).
3. `FlushInterval` of `00:00:00` or negative, `ChannelCapacity` of `0`: clamped to 1 second / default, never a
   tight loop or an unbounded channel (Task 1, Task 4).
4. The database is down for several flushes while a scanner floods the site: memory stays at the bound and
   the oldest entries go first (Task 4).
5. Two servers insert the same new URL at the same moment: one row, summed count (Task 6, SQLite and SQL Server).

### Task 2: URL normalisation

**Files:**
- Create: `src/code/Umbraco.Community.PageNotFoundTracker.Infrastructure/Tracking/TrackedUrlNormalizer.cs`
- Test: `src/test/Umbraco.Community.PageNotFoundTracker.Infrastructure.Tests/TrackedUrlNormalizerTests.cs`

**Interfaces:**
- Consumes: `NotFoundOccurrence` (spec 2), `TrackedUrlHit` (Task 1).
- Produces: `internal static class TrackedUrlNormalizer { static TrackedUrlHit Normalize(NotFoundOccurrence occurrence, bool includeQueryString, DateTime utcNow); }`
  returning `Count = 1`, `FirstSeen = LastSeen = utcNow`.

Rules (the algorithm the tests pin):
- Path: split off the query at the first `?`; `Uri.UnescapeDataString` (on failure keep the raw text); collapse
  repeated `/`; remove a trailing `/` except for `/`; lower-case invariant.
- `Url` = normalised path, plus `?` + query lower-cased when `includeQueryString` and the query is non-empty
  (parameter order kept as is: writer's call, not cheap enough to be worth it).
- `UrlHash` = lower-case hex SHA-256 of the full `Url` (before truncation). `Url` and `DisplayUrl` truncated to 2000.
- `DisplayUrl` = the original `PathAndQuery` as requested, without the query string when `includeQueryString` is off.
- `Domain` = `occurrence.Domain?.Name` lower-cased, else `""`. `Culture` = `occurrence.Culture ?? ""` (as returned).
- `RelativePath`: take the domain name, drop any `scheme://`, take the part from the first `/` (none -> no prefix),
  normalise it like a path; when the normalised path equals it or starts with it followed by `/`, remove it
  (result `/` when nothing remains). Never includes the query. Truncated to 800.

- [ ] **Step 1: Write failing tests** (`[TestCase]`s): `/About/` and `/about` give the same `Url` `/about`;
  `/a//b///` gives `/a/b`; `/` stays `/`; `/caf%C3%A9` gives `/café`; `/%E0%A4%A` does not throw;
  query off: `/x?b=1` gives `Url` `/x`, `DisplayUrl` `/x`; query on: `/x?B=1` gives `/x?b=1` and differs from
  `/x?b=2`; domain `localhost:44402/sitea` with `/siteA/About/` gives `Domain` `localhost:44402/sitea`,
  `RelativePath` `/about`; `/siteab/x` keeps `/siteab/x`; domain `https://www.sitea.local:44404/` gives
  `RelativePath` equal to the path; domain `null` gives `Domain` `""`, `Culture` `""`; 3000-char path gives
  `Url.Length` 2000, `RelativePath.Length` 800, and a hash different from a 2999-char path with the same prefix.
